# 실시간 협업 가이드

## 5. 실시간으로 코드를 같이 작성할 때 생길 수 있는 문제

| 문제 | 증상 | 현재 대응 | 사용할 때 주의 |
| --- | --- | --- | --- |
| 같은 줄 동시 편집 | 두 사람이 같은 줄을 고치면 글자가 섞이거나 순서가 바뀜 | Yjs(CRDT)가 글자 단위로 합쳐서 충돌 없이 저장됨 | 같은 줄은 한 사람만 고치는 게 안전. 큰 수정 전에는 채팅으로 알리기 |
| 한글 입력(IME) 조합 중 덮어씀 | 한글을 조합하는 도중 상대가 같은 위치를 수정하면 자모가 깨지거나 중복됨 | 조합이 끝난 글자는 정상 동기화됨 | 같은 줄에서 동시에 한글을 길게 입력하지 않기 |
| 네트워크 지연·끊김 | 입력한 내용이 늦게 보이거나 SYNC 표시가 OFFLINE으로 바뀜 | 끊겨도 로컬에 저장(IndexedDB)됐다가 재연결 시 합쳐짐 | OFFLINE 동안 쓴 내용은 브라우저를 닫지 말고 재연결을 기다리기 |
| 상대 커서 위치 착시 | 상대 커서가 실제와 다른 줄에 보일 수 있음 (문서가 바뀌는 중) | 이름표 커서를 실시간 표시 | 커서는 참고용. 정확한 위치는 채팅으로 줄 번호를 말하기 |
| 저장 타이밍 | 입력 직후에는 서버 저장이 끝나지 않았을 수 있음 | 입력 후 약 1.6초 뒤 동기화 상태 표시, 스냅샷은 별도 저장 | 중요한 구간은 `Ctrl+S`로 스냅샷을 남기기 |
| 스냅샷 복원 충돌 | 복원하면 다른 사람이 작업 중인 내용이 옛날 버전으로 바뀜 | 복원 전에 현재 내용을 PRE_RESTORE 스냅샷으로 자동 보관 | 복원은 혼자 있을 때, 또는 팀에 알리고 하기 |
| 권한 차이 | VIEWER는 읽기 전용인데 편집되는 줄 알고 기다리는 경우 | 탭에 READ-ONLY 표시, 서버에서 쓰기 차단 | 역할은 오른쪽 멤버 패널의 기호(@ 소유자, + 편집자, · 뷰어)로 확인 |
| 큰 파일·긴 줄 | 20만 자가 넘는 파일은 만들 수 없고, 긴 줄은 화면이 밀림 | 서버에서 크기 제한, 자동 줄바꿈 설정 제공 | 생성 파일은 나누고, 설정에서 자동 줄바꿈 켜기 |
| 동시 이름변경·이동 | 같은 파일을 두 사람이 옮기거나 이름을 바꾸면 트리가 깜빡임 | 서버가 이름 중복을 검사하고 파일 목록을 다시 그림 | 파일 구조 변경은 한 사람이 맡기 |

## 6. 코드 테스팅 방법

### 자동으로 돌리는 테스트

```bash
npm test                 # 단위 테스트 (vitest)
npm run test:integration # 실제 서버+DB로 API 통합 테스트
npm run test:e2e         # 브라우저 자동 테스트 (playwright)
npm run build            # 웹 빌드가 되는지 확인
```

- 통합 테스트는 `REQUIRE_DISCORD_SIGNUP=false`로 실행돼 디스코드 없이 가입 흐름을 검증합니다.
- 테스트용 서버와 실제 쓰는 서버를 동시에 켜지 마세요. 포트가 겹치면 엉뚱한 서버에 붙습니다.

### 손으로 확인할 때 (기능을 고친 뒤 체크리스트)

1. 브라우저 창 2개(또는 시크릿 창)로 두 계정 로그인 → 같은 파일 열기 → 한쪽에서 입력하면 다른 쪽에 바로 보이는지.
2. 한글을 빠르게 입력해 자모가 깨지지 않는지. 특히 상대가 같은 파일을 보고 있을 때.
3. 한쪽 인터넷을 끊었다가 (개발자도구 Network → Offline) 다시 연결해 내용이 합쳐지는지.
4. `Ctrl+S`로 스냅샷 → 내용 변경 → 기록(HISTORY)에서 DIFF와 복원이 되는지.
5. VIEWER 계정으로 열면 편집이 막히는지.
6. `.md` 파일에 한글로 글을 쓰고 미리보기에서 깨지지 않는지, 다운로드한 파일이 UTF-8로 열리는지.
7. 채팅 채널 4개(general/development/code-review/announcements)를 오가며 안 읽은 배지가 맞는지.

## 7. 유니티 작업 시 게임 화면을 어디에 띄울 것인가

**결정: 중앙 에디터 자리를 "게임 뷰" 탭으로 쓴다.**

- 지금 파일 탭이 있는 그 자리에 `GAME` 탭을 추가하고, Unity WebGL 빌드 결과물을 그 안에 iframe으로 띄웁니다.
  에디터와 게임 화면을 번갈아 보는 구조라 IRC/파일 패널 배치를 그대로 유지할 수 있습니다.
- 왼쪽 파일 패널은 Unity 프로젝트의 `Assets/` 트리를 그대로 보여주고, `.cs` 파일은 지금처럼 에디터로 엽니다.
- 하단 시스템 로그는 Unity 콘솔 출력(빌드 로그, play 에러)을 흘려보내는 곳으로 씁니다. 새 패널을 만들지 않습니다.
- 실행은 단축키로: `Ctrl+Enter` = 게임 뷰로 전환 + 최신 빌드 플레이. (단축키 체계는 Alt+1~4 패널 토글, Ctrl+P 파일 열기와 같은 결)
- 전제 조건: Unity 프로젝트를 WebGL로 빌드해 정적 파일로 서빙해야 합니다. 데스크톱 빌드( exe )는 브라우저에 띄울 수 없습니다.
- 하지 않는 것: 게임 화면을 오른쪽 멤버 패널이나 채팅 자리에 띄우지 않습니다. 너무 작고, 협업 정보가 가려집니다.
