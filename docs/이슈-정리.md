# Livebrary 이슈·운영 정리

## 0. 오류 확인 (배포 전 체크)

코드 변경 후·Oracle/Render 배포 전에 아래 순서로 확인합니다.

| 단계 | 명령 / 확인 | 통과 기준 |
|------|-------------|-----------|
| 의존성 | `npm install` | postinstall·Prisma generate 성공 |
| 단위 테스트 | `npm test` | vitest 전부 통과 |
| 통합 테스트 | `npm run test:integration` | 게이트·가입·권한 시나리오 통과 |
| E2E (선택) | `npx playwright install chromium` → `npm run test:e2e` | 브라우저 시나리오 통과 |
| 로컬 기동 | `npm run setup:local` → `npm start` | `http://127.0.0.1:3001` 응답 |
| 헬스 | `GET /api/health` | `{"ok":true,"database":"up",...}` |
| 한글 MD | 에디터에서 한국어 작성 → GET/ZIP 다운로드 | 메모장·VS Code에서 깨지지 않음 |
| 설정 | SET → 글자 크기 변경 | 터미널·에디터 글자 크기 동시 반영 |
| 채널 | 프로젝트 입장 후 `#general` 등 | 채팅 송수신, 툴팁에 용도 표시 |

**이 학교 PC에서의 확인 결과 (2026-10-19)**
- IDE 린트: 변경 파일(`Shell.tsx`, `i18n.ts`, `stores.ts`, `EditorPane.tsx`, `files.ts`, `projects.ts`) 오류 없음
- `git` / `node` / `npm`: PATH에 없음 → 단위·통합 테스트는 이 PC에서 실행하지 못함
- 배포·테스트는 GitHub에 올린 뒤 Oracle Ubuntu 또는 Node가 있는 PC에서 위 표대로 재확인

**자주 보는 런타임 오류**
- `입장 세션이 필요합니다` → 게이트에서 `join` 후 로그인
- Postgres UTF-8 초기화 실패 → 프로젝트 경로에 한글이 있으면 Windows 로컬 DB가 실패할 수 있음 (README 참고: 데이터는 `%LOCALAPPDATA%\livebrary\postgres`)
- Oracle HTTPS 실패 → DuckDNS 호스트명 필요, IP만으로는 무료 인증서 불가 (`deploy/oracle/setup.sh`)

## 1. MD를 한국어로 쓰면 깨지던 문제

**원인**
- Monaco 에디터 `fontFamily`에 한글 글꼴(D2Coding, 맑은 고딕 등)이 없어 Windows에서 글리프가 깨지거나 □로 보일 수 있음
- 단일 파일/ZIP 다운로드가 UTF-8 BOM 없이 나가면 구형 메모장 등이 CP949로 잘못 열어 한글이 깨짐

**조치**
- 에디터·UI 폰트 스택에 한글 폴백 추가
- 다운로드·ZIP 텍스트에 UTF-8 BOM 부여
- 설정 글자 크기가 UI에도 반영되도록 CSS 변수 연결

한글이 여전히 이상하면 설정에서 **CRT 주사선**을 끄고, **글자 크기**를 16 이상으로 올려 보세요.

## 2. 채널이 뭔지

채널은 **Discord가 아니라 프로젝트 안 IRC식 채팅방**입니다. 프로젝트 생성 시 기본 4개가 생깁니다.

| 채널 | 용도 |
|------|------|
| `#general` | 프로젝트 전체 잡담·공용 대화 |
| `#development` | 구현·작업 중인 내용 논의 |
| `#code-review` | 리뷰, diff, 머지 피드백 |
| `#announcements` | 소유자 공지 |

왼쪽 목록에서 채널에 마우스를 올리면 용도 설명이 뜹니다.  
관리자 콘솔의 Discord `#활동-로그` / `#보안-로그` / `#개발자-코드-로그`는 **서버 감사 로그용**으로, 위 채팅 채널과 다릅니다.

## 3. 터미널 입력창이 작음

- 프롬프트 줄 높이·입력칸 패딩·기본 하단 로그 패널 높이를 키움
- 설정 **글자 크기**를 올리면 프롬프트 줄도 같이 커짐

하단 LOG 패널은 경계선을 드래그해 더 키울 수 있습니다.

## 4. 폰트 크기 → 설정

`설정(SET)` → **글자 크기** (10–32).  
에디터와 터미널/채팅 UI에 함께 적용됩니다.

## 5. 실시간 코드 작성 시 발생할 수 있는 문제

| 문제 | 설명 | 대응 |
|------|------|------|
| 동시 편집 충돌 | 같은 줄을 두 명이 고치면 Yjs가 병합하지만, 의도한 코드와 다를 수 있음 | 역할 분담, `#code-review`로 소통, 스냅샷 자주 저장 |
| 오프라인/재접속 | 로컬 IndexedDB 초안과 서버 상태가 어긋날 수 있음 | 재접속 후 SYNC 상태 확인, 이상하면 스냅샷에서 복원 |
| VIEWER 권한 | 열람자는 읽기 전용, 로컬 수정이 서버에 안 감 | 편집 필요 시 EDITOR 초대 |
| 대용량 파일 | 파일당 약 20만 자 제한 | 큰 바이너리·에셋은 Git/Drive에 두고 코드만 Livebrary |
| Render 슬립 | 무료 티어는 유휴 시 잠듦 → 첫 접속 지연 | 협업 전에는 미리 깨워 두기 |
| Discord 미설정 | 감사 로그는 DB에만 쌓이고 Discord 전송은 재시도 대기 | 봇·채널 ID 설정 또는 무시하고 사용 |
| 네트워크 끊김 | WebSocket/Hocuspocus 끊기면 SYNC가 OFFLINE/ERROR | 새로고침 후 권한·문서 재동기화 |

기술 스택: Monaco + Yjs CRDT + Hocuspocus WebSocket. 문서 키는 `project:{uuid}:file:{uuid}`라 파일 이름 변경에도 연결이 유지됩니다.

## 6. 코드 테스팅 방법

저장소 루트에서:

```bash
npm install
npm run setup:local   # 최초 1회 (.env, embedded Postgres)
npm test              # 단위 테스트 (DB 불필요)
npm run test:integration   # 게이트·가입·권한 등 (로컬 Postgres)
npx playwright install chromium
npm run test:e2e      # 브라우저 E2E
```

수동 확인 체크리스트:
1. `npm run dev:local` → `http://127.0.0.1:5173`
2. 게이트에서 `join` → 가입/로그인
3. `/create`로 프로젝트 생성 후 두 계정(또는 두 브라우저)으로 같은 파일 동시 편집
4. `#general`에 메시지, `/msg` DM
5. 스냅샷 저장 → 비교 → 복원
6. ZIP/단일 파일 다운로드 후 한글 MD가 정상인지 확인

배포본은 [livebrary.onrender.com](https://livebrary.onrender.com)에서 동일 흐름으로 확인합니다.

## 7. 유니티 작업 시 게임 화면을 어디에 띄울지

Livebrary는 **웹 협업 코드 에디터**입니다. Unity Editor의 Game/Scene 뷰를 브라우저 안에 임베드하지는 않습니다.

권장 워크플로:
1. **스크립트·설정 텍스트** — Livebrary에서 같이 수정 (C# `.cs`, JSON, 셰이더 텍스트 등)
2. **Game / Scene 화면** — 각자(또는 화면 공유로) **로컬 Unity Editor**에서 실행
3. **빌드 결과물 공유가 필요하면** — WebGL 빌드를 별도 호스팅하고, 나중에 Livebrary 오른쪽 패널에 iframe 프리뷰를 붙이는 방향을 검토 (현재 미구현)
4. **에셋(`.unity`, `.fbx`, 텍스처 등)** — 바이너리는 Livebrary에 두지 말고 Git LFS / 드라이브 / Plastic 등 별도 저장소 사용

요약: **코드는 Livebrary, 플레이 화면은 Unity Editor(또는 WebGL 별도 창)**.
